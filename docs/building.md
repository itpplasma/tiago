# Building Tiago

## Default build

The default build needs CMake 3.24 or newer, a Fortran and a C compiler,
netCDF-C, libcurl 7.66 or newer and a Python 3 interpreter (used only by the
test suite's loopback archive server). OpenMP is used when found. CMake fetches
libneo, fortnum and json-fortran at pinned commits.

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

The `Makefile` wraps the same steps: `make` configures and builds, `make test`
rebuilds and runs `ctest --output-on-failure`, and `make clean` removes the
build directory. Extra cache entries go through `CMAKE_ARGS`, for example
`make CMAKE_ARGS="-DTIAGO_ENABLE_NATIVE_OPTIMIZATION=ON"`.

## Options

| option | default | effect |
|---|---|---|
| `TIAGO_ENABLE_OPENMP` | `ON` | OpenMP parallel loops in Tiago |
| `TIAGO_ENABLE_NATIVE_OPTIMIZATION` | `OFF` | optimise for the build machine (`-mcpu=native` on ARM, `-march=native -mtune=native` elsewhere); roughly halves the Biot–Savart kernel time through vectorisation |
| `TIAGO_ENABLE_SPECTRE` | `OFF` | SPECTRE plasma field source through libneo (needs HDF5) |
| `TIAGO_ENABLE_RECONSTRUCTION` | `OFF` | `tiago_reconstruct` and `tiago_infer`, see below |
| `TIAGO_LIBNEO_TAG` | pinned commit | libneo commit, branch or tag |
| `TIAGO_FORTNUM_TAG` | pinned commit | fortnum commit |

### Selecting the libneo revision

The libneo revision is chosen in this order:

1. `LIBNEO_BRANCH`, as a non-empty CMake variable or, failing that, an
   environment variable;
2. with `-DTIAGO_MATCH_LIBNEO_BRANCH=ON`, a libneo branch of the same name as
   the current Tiago branch, if one exists;
3. `TIAGO_LIBNEO_TAG`.

Branch matching is off by default.

## SPECTRE plasma source

```bash
cmake -S . -B build-spectre -DTIAGO_ENABLE_SPECTRE=ON
cmake --build build-spectre -j4
OMP_NUM_THREADS=4 ctest --test-dir build-spectre --output-on-failure
```

## Equilibrium reconstruction

`tiago_reconstruct` and `tiago_infer` need VMEC++, whose exact force Jacobian
is generated by Enzyme. This requires Clang with the matching Enzyme plugin and
LAPACK. The tested toolchain is Clang 20.1.8 with Enzyme v0.0.264 (commit
`f06646a6d8a6a69a123c7b4184f8db261c03216d`):

```bash
sudo apt-get install clang-20 llvm-20-dev libclang-20-dev lld-20 libomp-20-dev \
    libzstd-dev liblapack-dev ninja-build
git clone --depth 1 --branch v0.0.264 https://github.com/EnzymeAD/Enzyme.git
test "$(git -C Enzyme rev-parse HEAD)" = f06646a6d8a6a69a123c7b4184f8db261c03216d
cmake -G Ninja -S Enzyme/enzyme -B enzyme-build -DCMAKE_BUILD_TYPE=Release \
    -DLLVM_DIR=$(llvm-config-20 --cmakedir) \
    -DClang_DIR=$(llvm-config-20 --prefix)/lib/cmake/clang
ninja -C enzyme-build ClangEnzyme-20
CXX=clang++-20 cmake -S . -B build-vmecpp -G Ninja -DCMAKE_BUILD_TYPE=Release \
    -DTIAGO_ENABLE_RECONSTRUCTION=ON \
    -DTIAGO_ENZYME_PLUGIN=$PWD/enzyme-build/Enzyme/ClangEnzyme-20.so
cmake --build build-vmecpp
OMP_NUM_THREADS=1 ctest --test-dir build-vmecpp --output-on-failure
```

Clang 22.1.8 with the Enzyme 0.0.293-1 distribution package has also passed the
full test suite at one and four threads (tested `ClangEnzyme-22.so` SHA256
`8878aaf985a4315922efc095cdafdb4ca8e9df799c2c78371e8463b0762d242a`).

CMake accepts Clang major versions 20 and 22 and checks that the plugin loads.
`-DTIAGO_EXPERIMENTAL_ENZYME_TOOLCHAIN=ON` allows other versions for
development; it does not establish that derivatives are correct, so run the
derivative tests in any case.

With reconstruction enabled, CMake additionally fetches VMEC++ (built as a C++
library without its Python module) and fortplot (figures) at pinned commits.
VMEC++ downloads HDF5 and netCDF-C sources; if these are unreachable, point
`-DTIAGO_VMECPP_HDF5_URL=` and `-DTIAGO_VMECPP_NETCDF_URL=` at local copies.
