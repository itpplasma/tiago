# Contributing to TIAGO

## Source provenance (strict)

TIAGO is written clean-room with respect to other codes, from public
knowledge and from our own code. Nobody, human or agent, contributes code,
tests, generators, documentation or reviews to TIAGO while having non-public
code of others in their working context.

- **Allowed:** published papers, theses, books, public reports and
  documentation, and code under an OSI-approved open-source licence whose
  repository and commit are recorded. Permissively licensed code (MIT, BSD,
  Apache 2.0) may be studied and reused with its licence notice. GPL and LGPL
  code may be studied, but no code, translation or close paraphrase is taken
  from it.
- **Our own repositories** may be read and reused when the code in them is
  written by us and is neither a fork nor a copy of someone else's
  non-public code.
- **Non-public code** is every other implementation in any form: source,
  binary, decompilation, excerpt, or a description of its implementation that
  is not itself a publication. This includes closed-source code, code
  obtained under an access or user agreement, publicly visible code without an
  open-source licence and code shared privately. Code becomes allowed only
  when it is published under an open-source licence, and from that version on.
- **No contamination:** non-public code is not opened, searched, run or
  summarised during TIAGO work. A session that has had non-public code in its
  context does not write, design or review TIAGO material. If non-public
  material enters a session, stop and do not submit that session's output.
- **Comparisons** in this repository, its docs and tests use open-source codes
  run on public or synthetic inputs. Codes that are not open source enter only
  through their published results, and nothing here refers to access to them.
- **Record the sources:** each capability lists in its document under `docs/`
  the papers and open-source repositories (with commit and licence) used for
  its derivation, implementation or validation. Changes, commit messages and
  issues do not restate this rule.
